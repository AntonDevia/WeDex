# Архитектура и границы первой версии

```
egui: Sonora / поиск / медиатека
       │ сообщения и идентификаторы запросов
       ├── Last.fm: граф похожих треков → очередь метаданных
       ├── Services: Yandex → Hitmotop → SoundCloud → YouTube Music
       │              │
       │              └── сопоставление записи → URL перед воспроизведением
       ├── Player: аудиопоток в RAM → Symphonia → EQ → CPAL
       ├── Recognition: CPAL → моно/16кГц → Shazam fingerprint → поиск
       └── Store: SQLite + Windows Credential Manager
```

`src/app.rs` содержит состояние интерфейса и обработку событий фоновых задач. Поиск и разрешение записи выполняются вне UI. Идентификаторы запросов отклоняют устаревшие результаты поиска, распознавания, плейлистов и разрешения трека. Аудиопотоки дополнительно проверяют поколение воспроизведения, чтобы предыдущая загрузка не включилась после переключения.

`src/providers/lastfm.rs` использует `track.getSimilar`, `artist.getSimilar`, `artist.getTopTracks`. Открытия переставляют части ранжированного списка, исключаются уже поставленные в очередь и недавно прослушанные записи, на исполнителя приходится до двух треков за подборку. Профиль и scrobbling не требуются и пока не реализованы. Запросы на дозаполнение ограничены сменой позиции очереди: пустой ответ или ошибка не вызывают повторных запросов каждый кадр.

`src/providers/yandex.rs` изолирует неофициальный API. Авторизация передаётся только на API Яндекса. Полный поток выбирается из непревью MP3-вариантов `download-info`; ссылка вычисляется только перед проигрыванием. Собственная радиостанция Яндекса не вызывается.

`src/providers/external.rs` содержит независимые адаптеры. Внешний поиск выполняется параллельно, при выборе аудио приоритет сервисов последовательный. YouTube Music не выдаётся за надёжный источник нативного аудио: отсутствие открытого формата считается явным ограничением. У SoundCloud используются URN, официальный OAuth и MP3 HLS без подмены полного трека превью. AAC HLS требует отдельного демультиплексора; этого слоя пока нет.

`src/audio.rs` владеет аудиоустройством в отдельном потоке. Сетевой загрузчик прогрессивно наполняет ограниченный буфер, декодер получает интерфейс `Read + Seek`. Отмена проверяется при чтении и загрузке, обрыв Content-Length отмечается ошибкой. EQ — 10 пиковых biquad-фильтров с отдельной историей для каждого канала; положительное усиление компенсируется предусилением. Это не loudness normalization и не профессиональный limiter. Нет gapless/crossfade, выбора выходного устройства и системных медиаклавиш; они относятся к следующим итерациям.

`src/recognition.rs` записывает звук только по явному нажатию кнопки и предоставляет отмену. Низкочастотный sinc-фильтр перед уменьшением частоты дискретизации подавляет алиасинг. Три upstream-модуля fingerprinting адаптированы из ShazamIO Core с сохранением MIT-лицензии, Python-обвязка не используется.

`src/store.rs` разделяет собственные лайки, актуальный импорт Яндекса, историю и выбранные замены записей. Импорт заменяется транзакционно. В БД нет OAuth-токенов, URL аудиопотоков или аудиозаписей. Конфигурация хранит громкость, EQ, исходный трек и параметры рекомендаций.

## Что нужно для полноценного ежедневного клиента

1. Сквозная проверка Яндекса с пользовательским токеном: приватные плейлисты, региональная доступность, отсутствие полного потока, обновлённые схемы API. При отказе `download-info` нужен отдельный адаптер актуального доступного account-authorized transport.
2. Проверка распознавания на реальном микрофоне и нескольких типах устройств. Для Shazam — сетевые contract-тесты на разрешённых тестовых аудиозаписях.
3. SoundCloud: полноценная регистрация приложения, PKCE/refresh и AAC HLS вместо ручного ввода access token и зависимости от старого MP3 HLS.
4. YouTube Music: выбрать и реализовать поддерживаемый способ воспроизведения с учётом авторизации и актуальных требований платформы. Текущий вариант покрывает поиск и открытые прямые форматы. Сигнатуры, SABR, DRM и автоматический перенос браузерных cookies не реализованы.
5. Hitmo: используется актуальный адрес https://ru.hitmo-top.cc/. Поиск, обложки, страницы песен и начало MP3-потока проверены живым запросом. Следить за изменениями адреса и разметки каталога; автоматического обхода проверок браузера нет.
6. Улучшить Sonora сигналами быстрых пропусков, баном треков/артистов, кэшированием графа и предразрешением следующих записей. Сейчас недоступный трек требует ручного пропуска; подписка Яндекса не гарантирует наличие любого произведения в каталоге.
7. Версии без цензуры: при наличии подтверждённых источников добавлять доказательства/идентификаторы записи. Полностью автоматического доказательства «без цензуры» по метаданным в проекте нет.
8. Добавить Authenticode-подпись Windows и дополнительную проверку чистой Windows-машины. Обновления GitHub Releases и CI release реализованы; см. UPDATES.md.
