# Локальное облако WeDex · прототип 0.6.2

## Что работает

- Запуск HTTPS/WSS-сервера из «Настройки → Моё облако» в фоновом потоке; UI остаётся отзывчивым.
- Отдельная база сервера, собственная TLS-идентичность, одноразовые приглашения и отдельные ключи устройств.
- Браузерный пульт для ПК и телефона; несколько нативных клиентов могут подключаться к одному серверу.
- Управление конкретным играющим устройством: play/pause, next/previous, seek, volume, shuffle, repeat, queue index.
- Повтор команды с тем же идентификатором не выполняется второй раз. Команды для недоступного устройства не ждут его возвращения в сеть.
- Локальное накопление сессий, пакетная синхронизация с подтверждением ревизий, суммарное время и топ треков.
- Отзыв другого устройства владельцем локального сервера. Ключ отозванного устройства больше не авторизуется.
- Отдельный CLI-бинарник серверного пакета. GUI, аудиодрайверы, Windows tray и сервисные аккаунты музыкальных провайдеров ему не нужны.

## Быстрый запуск

1. Открыть WeDex 0.6.2 и «Настройки → Моё облако».
2. Оставить выключенным «Доступ из домашней сети», нажать «Запустить сервер».
3. Дождаться состояния «Облако подключено». Плеер автоматически регистрируется на своём сервере.
4. Создать приглашение для браузера и открыть пульт. Принять сертификат своего локального сервера в браузере, затем нажать «Подключиться».
5. Запустить музыку в WeDex и управлять ею из вкладки браузера. Пульт сам не выводит звук.

Для другого WeDex используется строка `wedex-cloud:…` из кнопки «Пригласить WeDex». Внутри адрес, сертификат и одноразовый код. Эта строка предоставляет право привязать устройство; не публикуйте её. Ключ уже привязанного устройства хранится в Windows Credential Manager, а не в обычных настройках.

Браузер хранит собственный ключ в sessionStorage текущей вкладки. Закрытие вкладки может потребовать нового приглашения. Адрес приглашения сразу очищается от кода после загрузки страницы. Данные и интерфейс пульта обслуживаются самим сервером, внешние CDN не нужны.

## Телефон в домашней сети

Перед запуском сервера включить доступ из домашней сети. WeDex начнёт слушать все IPv4-интерфейсы на порту 8765 и покажет LAN-адрес. Выбирать этот режим следует для доверенной домашней сети. При необходимости разрешить приложению входящие соединения в частном профиле Windows Firewall.

ПК и телефон должны иметь возможность соединиться внутри сети. Гостевой Wi-Fi, изоляция клиентов роутером и firewall могут препятствовать этому, даже если имя Wi-Fi одинаковое. Сервер не открывает порты на роутере. Доступ через мобильный интернет в этот этап не входит.

Создать новое приглашение для браузера и передать ссылку на телефон. При первом открытии ожидается предупреждение браузера о собственном сертификате. Нативный клиент получает сертификат по приглашению и использует его для проверки TLS, не отключая проверку сертификатов.

LAN-адрес добавляется в сертификат при первом создании сервера. Если адрес ПК изменился, приглашение на новый IP может не пройти нативную TLS-проверку. Автоматическое обновление SAN/сертификата и подтверждение нового доверия относятся к следующей версии; глобальное отключение TLS-проверки не используется как обход.

## Данные и запуск без плеера

Данные приложения: каталог `data_dir()` из `src/store.rs`. Данные встроенного сервера находятся в его подпапке `cloud-server`:

- `cloud.sqlite3`, `cloud.sqlite3-wal`, `cloud.sqlite3-shm` — база и рабочие файлы SQLite;
- `identity.json` — административный секрет сервера;
- `certificate.pem`, `private-key.pem` — TLS-идентичность;
- `server.lock` — блокировка каталога от одновременного запуска второй службы.

Идентичность и приватный ключ не входят в дистрибутив. На Unix каталог создаётся с правами 0700, секретные файлы — 0600. На Windows встроенный сервер использует пользовательский LocalAppData и унаследованные права этого каталога.

Отдельный запуск:

```powershell
.\WeDex-Server.exe --data-dir C:\WeDexCloud --bind 127.0.0.1:8765
```

По умолчанию CLI использует каталог `wedex-cloud-data` относительно рабочей директории. Сервер выводит одноразовые приглашения для подключения. Завершение — Ctrl+C. Для обычного пользователя достаточно кнопки внутри WeDex; устанавливать дополнительную Windows-службу не требуется.

Сборка серверного пакета из исходников:

```text
cargo build -p wedex-cloud --release --bin wedex-server
```

Пакет `crates/wedex-cloud` не зависит от desktop-пакета. Самостоятельный сервер на Linux пока не проверен сквозным развёртыванием; SSH-установщик и systemd-релиз ещё не готовы.

## Правила статистики этой версии

Записи создаёт только фактически играющее устройство. На ПК сохраняется UUID сессии, трек, момент начала, накопленные миллисекунды и ревизия. Очередь отправки долговечна, подтверждения относятся к конкретному серверу и конкретной ревизии. Запись новой ревизии во время отправки предыдущей не теряется.

Учёт использует продвижение позиции и монотонное время. Большие скачки позиции, пауза, loading, ошибка и длинные разрывы обновления не добавляют фиктивные секунды. Запись контрольной точки выполняется примерно раз в пять секунд, при остановке/смене трека и при нормальном выходе. При аварийном завершении могут потеряться последние секунды до контрольной точки.

Это статистика основных воспроизводимых треков: при crossfade исходящая дополнительная дорожка отдельно пока не учитывается. Одновременное прослушивание на двух устройствах суммируется; поле называется временем на устройствах и не выдаётся за объединённые минуты активности пользователя. Порог полного прослушивания, годовые карточки, календарь и жанры ещё не реализованы.

Прошлая история из 500 запусков остаётся для рекомендаций. Преобразования её в выдуманные прошлые минуты нет.

## Проверки

Тесты серверного пакета поднимают настоящий HTTPS/WSS-сервер во временной папке и подключают независимые клиенты. Проверяются одноразовое приглашение, проверка сертификата, команды с подтверждением и повтором, запрет статистики от браузера-пульта, сохранность после перезапуска, отзыв доступа и защита базы от второго процесса.

Desktop-тесты проверяют прохождение удалённых команд через диспетчер настоящего приложения, повтор абсолютной паузы, очередь, громкость, seek, идемпотентный shuffle, накопление времени и поведение полей в окне облака.

## Следующие этапы

Android 0.6.2 подключается по приглашению WeDex. Пульт находится в основном мини-плеере и дзене; значок наушников открывает выбор устройства. От ПК передаются обложка, очередь и состояние; аппаратные кнопки телефона управляют громкостью выбранного ПК. Новые команды лайка, эквалайзера и запуска треков требуют Windows 0.6.2. Подробности — в [ANDROID.md](ANDROID.md).

Windows 0.7.0 добавляет встроенный Linux-сервер и мастер SSH-установки по IP/логину/паролю или ключу. Инструкция и ограничения — [VPS_SETUP.md](VPS_SETUP.md). Telegram-архив, постоянный кеш Hitmo, согласованная синхронизация медиатеки и годовая статистика ещё не реализованы.
