# Обновления WeDex

Исходники и релизы: https://github.com/AntonDevia/WeDex. В приложении используется публичный GitHub Releases API; аккаунт GitHub пользователю не нужен. Проверка запускается при старте, затем каждые шесть часов; вручную — «Настройки → Обновления». Установка начинается только по кнопке пользователя.

## Windows и Android

Релиз `v0.8.3` содержит `WeDex-Windows.exe` и `WeDex-Android.apk`. Для отдельных платформ можно публиковать теги `windows-vX.Y.Z` и `android-vX.Y.Z`. Файлы скачиваются через официальный API assets с `Accept: application/octet-stream`; проверяются версия, размер и SHA-256 из метаданных GitHub. Неполный или повреждённый файл не устанавливается. Архивы для обновления не нужны.

Windows скачивает EXE в каталог данных пользователя, ждёт закрытия приложения, оставляет предыдущий EXE рядом с ним и запускает новую версию. Приложение должно находиться в доступном пользователю для записи каталоге. Автономная Windows-сборка пока не подписана Authenticode.

Android открывает системное окно установки APK. При первом обновлении Android может попросить разрешить установку из WeDex. Подпись должна совпадать с уже установленной версией; обновление сохраняет данные приложения. Ключ текущей подписи нужно хранить и резервировать отдельно от публичных исходников.

## Сервер VPS

Сервер выпускается независимо: `server-vX.Y.Z`, файл `wedex-server-x86_64-linux-musl`. Обновление сервера предлагается на ПК владельца подключённой VPS. Нажатие «Обновить VPS» отправляет авторизованный запрос по закреплённому TLS-сертификату; повторно вводить SSH-пароль не нужно.

Установщик создаёт `wedex-update.path` и отдельную службу обновления. Основной сервер работает от пользователя `wedex`; привилегированный обработчик самостоятельно проверяет официальный релиз, его SHA-256 и версию бинарника. Перед переключением сохраняются SQLite и идентичность сервера. Проверяется запуск новой службы; при неудаче возвращается предыдущий бинарник. Откат произвольных будущих несовместимых миграций базы не гарантируется.

Для серверов, установленных WeDex 0.7, сначала один раз повторите SSH-установку из нового приложения. Она добавит службу обновления и сохранит данные. После этого последующие обновления выполняются одной кнопкой. Локальный сервер внутри Windows-приложения обновляется вместе с приложением.

## Подключения между устройствами

После привязки нативных клиентов к одному облаку синхронизируются OAuth-токен Яндекса, ключ Last.fm, токен SoundCloud и выбранный домен Hitmo, включая очистку подключения. Изменения без сети отправляются после восстановления связи. Секреты шифруются на устройстве XChaCha20-Poly1305; в базе сервера остаётся шифротекст. На устройствах используются Windows Credential Manager и Android Keystore.

Ключ шифрования передаётся только внутри приглашения «Пригласить WeDex». Не публикуйте приглашение и передавайте его доверенным способом. Браузерный пульт не получает доступ к ключам сервисов. Для устройств, привязанных до версии 0.8, создайте на ПК новое приглашение WeDex и импортируйте его на телефоне один раз; повторная привязка к тому же серверу сохраняет существующее устройство.

SSH-пароли, ключ владельца сервера и персональные ключи устройств между устройствами не копируются. Общая медиатека и музыкальные файлы пока не синхронизируются.

## Публикация

Сначала измените версии приложения в `Cargo.toml`, `android/app/build.gradle` (включая возрастающий `versionCode`) и при необходимости серверного пакета, обновите `Cargo.lock`. Соберите Linux-сервер, затем Windows и Android. Тесты: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`.

Издатель может собрать релиз на своём ПК и загрузить EXE/APK через `gh release create TAG --repo AntonDevia/WeDex` и `gh release upload TAG FILES --repo AntonDevia/WeDex`. Имена файлов должны совпадать с указанными выше. GitHub вычисляет digest при загрузке; до его появления проверка не предлагает такой файл.

Workflow `.github/workflows/release.yml` также собирает сервер и Windows по тегам. Для Android-сборки в Actions владелец отдельно разрешает хранение ключа подписи в закрытых Secrets и включает переменную репозитория `ANDROID_RELEASES_ENABLED=true`. Нужны Secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Закрытые ключи в Git и release assets не добавляются. Без этого Android-релиз собирается и подписывается на ПК.

При форке измените `WEDEX_UPDATE_REPOSITORY=owner/repo` во время сборки приложения и настройку `update_repo` в `/etc/wedex/server.json` через SSH. Серверный обработчик использует собственную настройку репозитория, а не URL из клиентского запроса.
