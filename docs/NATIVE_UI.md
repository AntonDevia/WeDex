# Нативный интерфейс WeDex

Исходный дизайн: [Figma · Sonora](https://www.figma.com/design/hh9WPK6OnPYis1tL7S0jDY?node-id=8-157). Компоненты, Medeo Sans / Display и логотип Flow встроены в Rust-приложение. По последнему запросу приложение использует светлую и тёмную темы и адаптивную компоновку вместо фиксированного холста 1440×960. Документ Figma не изменялся.

## Устройство

Поиск и страница исполнителя в версии 0.3.0 собираются в `src/glass/search.rs` из тех же шрифтов, материалов и кнопок. Их шапка неподвижна, правая панель освобождает место под результаты. `Layout::for_page` рассчитывает полную ширину поиска; внешний контейнер не получает прокрутку. Колесо обрабатывается только видимым списком с учётом его обрезки. На низких окнах карточка артиста стоит рядом с фильтрами, на узких источники обозначаются логотипами. Каталог артиста использует отдельное состояние и номер запроса, чтобы старый сетевой ответ не подменял нового исполнителя. Страницы по 100 записей подгружаются у конца списка; уже загруженные строки остаются на месте.

- `design/native-scene.json` — геометрия, матрицы, цвета, материалы, шрифты и вложенные слои 25 шаблонов из текущего файла Figma. Разные треки Sonora и содержимое плейлистов подставляются в общие шаблоны.
- `design/native-text-layout.json` — ширины автоматически измеренных текстов Figma. Нативный рендерер учитывает различие метрик и сглаживания шрифтов.
- `tools/prepare_native_design.py` компилирует эти данные в `assets/ui/scene.json` и таблицу встроенных ресурсов. `tools/brand-assets/render-fontawesome.mjs` и `tools/normalize_fontawesome.py` готовят Font Awesome Free Solid. Полные скриншоты экранов остаются только визуальными эталонами.
- `src/glass/scene.rs` — типизированные слои и преобразования повёрнутых карточек. `layout.rs` рассчитывает размеры по окну: меню на всю высоту, сетки с 1–6 колонками, компактный плеер и панели с прокруткой. `theme.rs` применяет выбранную тему и версию приложения под логотипом.
- `src/glass/render.rs` — отрисовка, обрезка списков, изображения, типографика и привязка областей управления. Обложки сервисов загружаются асинхронными загрузчиками egui.
- `src/glass/blur.rs` — настоящий Gaussian backdrop blur OpenGL. `composite.rs` применяет прозрачность целой группы после её отрисовки, как в Figma.
- `src/glass/motion.rs` — два состояния Ambient с семисекундными переходами. Переход карусели за 200 мс меняет преобразование готовых карточек, сохраняя маски теней и размеры растеризации шрифтов. Повторное переключение продолжает движение с текущего положения. Текст растеризуется с двукратным разрешением; края изображений сглаживаются прозрачной каймой в один физический пиксель. Навигация длится 200 мс, открытие панели — 200 мс. Учитывается настройка анимаций Windows; `WEDEX_REDUCED_MOTION=1` отключает движение.
- `src/glass/mod.rs` — привязки данных, навигация и панели. На выходе — `Intent`, который обрабатывает существующая логика `src/app.rs`.

Интерфейс работает с реальными результатами сервисов. Прототипные состояния подключения и распознавания заменены фактическими статусами. Ввод ключей добавлен в том же оформлении, поскольку в интерактивном макете реальные формы авторизации отсутствовали. Ключи сохраняются через Windows Credential Manager.

## Проверка

`cargo test --locked` проверяет также нативное попадание по кнопкам, закрытие модальных панелей, запуск поиска клавиатурой, очищение запроса, распознавание, перемотку, громкость, отдельные полосы EQ, сохранение версии и прокрутку. Проверка ресурсов находит каждый видимый вектор и изображение из слоёв.

`python tools/capture_native_ui.py sonora search results library favorites playlists playlist queue eq eq-warm sources tune recognition versions` запускает изолированные нативные состояния и сохраняет PNG в `.local/ui-captures/`. В этом режиме не открывается база пользователя, не читаются ключи и не выполняются запросы к музыкальным сервисам. Обычный запуск `.exe` работает с данными пользователя.

`WEDEX_PREVIEW_MOTION=1` включает движение фона в изолированном режиме для ручной проверки полного цикла. `tools/package_glass_release.py` упаковывает проверенный executable вместе с лицензиями.

`WEDEX_PREVIEW_SIZE=480x800` задаёт размер окна для проверки адаптивной компоновки. Снимки сохраняются с размером в имени. Состояние `error` проверяет общий путь обработки ошибки: нейтральное уведомление и подробная запись `preview-service` в `WeDex-errors.log` рядом с `.exe`. F11 переключает полноэкранный режим. Скрипт подготовки релиза копирует файлы в `dist/WeDex-0.1.1` без создания ZIP.

Перемотка применяется после отпускания указателя; движение по таймлайну меняет только предварительно выбранную позицию. `src/diagnostics.rs` дописывает ошибки с временем UTC и версией приложения. Сохранённые ключи и токены скрываются перед записью.

## Подготовка очереди и темы (0.1.1)

В настройках есть «Как в системе», «Светлая», «Тёмная». Выбор сохраняется в SQLite вместе с остальными параметрами, системный режим реагирует на изменения темы Windows. `WEDEX_PREVIEW_DARK=1` позволяет проверить тёмную палитру в изолированном режиме; состояние `settings` открывает настройки.

`App::prepare_upcoming` заранее разрешает три ближайшие рекомендации Last.fm в записи каталогов. `Renderer::preload_covers` прогревает загрузчик текстур независимо от того, виден ли слой обложки. Идентичность карточек привязана к позиции в очереди: обновление метаданных не имитирует переключение трека.

`audio/preload.rs` хранит один следующий декодер с независимым токеном отмены. Переход к нему забирает результат существующей загрузки. При переходе во время подготовки ожидается та же задача; повторный сетевой запрос не запускается. `audio/download.rs` восстанавливает прерванное чтение с проверкой Content-Range и ETag. Подробности не содержат подписанных URL.

Чтение каталогов и метаданных повторяется при сбросе соединения и временных ответах сервера. HTTP 403 не повторяется на том же запросе каталога; аудиоподготовка отдельно обновляет адрес потока. Если сеть восстановилась, уже загруженные байты аудио сохраняются.

Проверки охватывают раннюю загрузку ещё невидимой обложки, передачу готового декодера, отмену старой подготовки, восстановление HTTP после обрыва без дублирования байтов, сохранение темы и смену системного оформления. Отдельный игнорируемый тест `live_yandex_preload_decodes_audio_before_playback` подготавливает реальную запись с настроенным аккаунтом, не открывая аудиовыход.

Логотипы подключённых сервисов встроены из `assets/providers`; прозрачные поля обрезаны перед приведением к общему видимому размеру. Источники и лицензии перечислены в `assets/providers/sources.json`.

## Очереди и обновление Sonora (0.1.2)

Щелчок по песне в «Понравившемся» или плейлисте передаёт приложению весь упорядоченный список с индексом выбранной песни одним действием `PlayCollection`. Источник воспроизведения хранится отдельно от открытой вкладки: рекомендации не пополняют очередь коллекции, даже когда пользователь переходит на экран Sonora. После последнего трека коллекция останавливается. Поздние ответы предыдущего запроса Sonora отклоняются по идентификатору и источнику очереди.

Кнопка «Сбросить» очищает исходный трек, отменяет старый подбор и запускает новый по четырём случайным песням из всей коллекции понравившегося. Сохраняется история последних исходных треков и выданных рекомендаций; недавно использованные записи получают меньший вес. Подбор в `src/discovery.rs` использует случайную выборку с весами рейтинга Last.fm, ограничивает выдачу двумя песнями исполнителя и разносит соседние песни одного артиста. Повторы остаются возможными, особенно при небольшом каталоге; жёсткого запрета навсегда нет.

Регрессионные проверки имитируют естественное окончание треков без аудиоустройства и сетевых запросов, проверяют переходы коллекции, конец плейлиста, отмену старой выдачи, источник сброса и работу кнопки на узком экране. Отдельный сетевой тест запрашивает два потока Last.fm и сравнивает порядок.

## Настройки и полноэкранное прослушивание (0.2.0)

В 0.2.4 `lyrics_view.rs` выводит текст дзена без панели; активная строка увеличивается вдвое, перемещение, размер и выделение меняются за 200 мс. Перенесённые строки центрируются внутри фрагмента. `transitions.rs` хранит прерываемые переходы значений и стилей кнопок; исчезающее управление не принимает ввод. Плеер имеет отдельный ряд таймлайна, центральное управление и радиус 24 px, совпадающий с меню. Подробности: [RELEASE_0.2.4.md](RELEASE_0.2.4.md).

`src/glass/panels.rs` строит адаптивные стеклянные настройки, EQ, текст, вертикальную громкость и дзен. Пустые области панелей перехватывают щелчки; на узких экранах длинные панели прокручиваются. Все вкладки используют Ambient Sonora. Подпись рекомендации центрируется относительно области Sonora и показывает исходный трек полужирным.

`src/lyrics.rs` использует LRCLIB v1 get/search, проверяет исполнителя, название и длительность, разбирает LRC timestamps/offset/repeated tags. Запросы асинхронны, кэш до 40 записей; поздний ответ не заменяет текст нового трека. Включение сохраняется в Settings; по умолчанию запросы отсутствуют.

`src/audio/engine.rs` удерживает два Sink при crossfade. Независимые токены отмены сохраняют исходящий поток до конца затухания. `ramp.rs` меняет усиление по сэмплам; Pause/Seek/Stop согласованы с обоими потоками. Автопереход требует готового следующего буфера и срабатывает один раз на ticket. Повтор текущего трека отключает автоналожение.

`src/tray.rs` создаёт Windows tray icon на потоке окна; действия меню будят egui. CancelClose + Visible(false) сохраняют плеер; Quit обходит сворачивание. При ошибке создания трея окно закрывается обычным способом. `WEDEX_PREVIEW_TRAY=1` позволяет изолированно проверять трей без аккаунтов и базы.
