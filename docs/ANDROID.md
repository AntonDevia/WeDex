# WeDex для Android · 0.8.2

Нативная Android-версия использует тот же Rust-код, сцену интерфейса, Medeo, Font Awesome, стекло и анимации, что и Windows. Это APK с Rust/egui/OpenGL ES и небольшим Android-слоем для клавиатуры, защищённого хранения и системного плеера.

## Установка

Файл: `dist/WeDex-Android-0.8.2/WeDex-0.8.2-Android.apk`.

Поддерживаются Android 8.0+ (API 26), ARM64 и x86_64, OpenGL ES 3.0. Для обычных телефонов используется ARM64. 32-битный ARM в этот APK не включён. Это сборка для установки напрямую, с локальной отладочной подписью; публикация в Google Play не выполнялась. Сохранение этой подписи необходимо для установки следующих обновлений поверх имеющейся версии.

Подключения добавляются в «Настройки → Подключения». Аккаунты и ключи пользователя не включены в APK. Для вставки длинного ключа или приглашения предусмотрена кнопка «Вставить». Проверка сервиса запускается автоматически после редактирования, как на ПК. Сохранённые ключи зашифрованы AES-GCM, ключ шифрования находится в Android Keystore. Резервное копирование данных приложения средствами Android отключено.

## Возможности

- Sonora, запуск от понравившихся, подбор от трека, сброс, характер потока, подготовка следующего аудио и обложек.
- Поиск по источникам, исполнители и их каталоги, распознавание с микрофона, медиатека и плейлисты.
- Общий аудиодвижок, очередь и история, перемотка после отпускания ползунка, перемешивание и повтор, crossfade, десять полос эквалайзера ±12 дБ и предусиление, пресеты.
- LRCLIB, синхронный текст, увеличение активной строки, ручная прокрутка с возвратом через три секунды, дзен.
- Светлая, тёмная и системная темы, общий ambient-фон.
- Подключение к личному облаку, статистика и пульт по тому же HTTPS/WSS-протоколу, что на ПК.

Условия и ограничения музыкальных сервисов сохраняются: Last.fm не отдаёт аудио, для Яндекса нужен собственный токен с подходящей подпиской, каталог и воспроизведение внешних источников зависят от их доступности. Гарантия оригинальной версии по одному тегу Explicit не даётся.

На телефоне навигация находится снизу. Мини-плеер занимает одну строку: обложка, название/исполнитель, лайк и плей/пауза. Нажатие на обложку или данные трека открывает дзен. В дзене большая обложка остаётся без кнопок; ниже расположены данные трека, таймлайн, перемешивание, предыдущий/следующий трек, воспроизведение и лайк. Очередь и облачный пульт находятся сверху, повтор, текст и эквалайзер — под основным управлением. Включённый текст занимает область обложки, а управление остаётся доступным. Нижний баннер запускает Sonora по текущему треку.

Списки прокручиваются пальцем, карточки Sonora переключаются горизонтальным жестом, длительное нажатие на трек открывает его действия. При локальном воспроизведении системные кнопки регулируют мультимедийную громкость Android; при управлении ПК — громкость выбранного ПК. «Назад» закрывает панель/дзен, затем возвращает Sonora и сворачивает приложение.

## Фоновое воспроизведение

Android foreground service показывает системный MediaSession-плеер с паузой, предыдущим/следующим треком и перемоткой. Аудио остаётся в Rust; отдельный фоновый цикл обслуживает очередь и облако, когда экран приложения не рисуется. Обрабатываются audio focus и отключение наушников. В настройках можно остановить музыку при уходе в фон.

Обычное сворачивание и выключение экрана поддерживаются. Принудительная остановка, удаление задачи и уничтожение процесса системой завершают текущую сессию. Восстановление незавершённой очереди после уничтожения процесса пока не реализовано. Прошивка телефона может дополнительно ограничивать фоновую работу.

## Подключение к ПК

1. В Windows WeDex открыть «Настройки → Моё облако», включить доступ из домашней сети и запустить сервер.
2. Создать приглашение для WeDex и передать его на телефон.
3. На Android открыть «Настройки → Моё облако», указать имя телефона, вставить приглашение и подключиться.
4. Играющий ПК автоматически появляется в обычном мини-плеере и дзене: обложка, название, таймлайн и очередь. Выбор устройства находится под значком наушников в дзене. Настройки на телефоне служат только для подключения.

Пауза, переключение, перемотка, лайк, перемешивание, повтор и эквалайзер в основном плеере управляют выбранным ПК. Можно отправить ему трек или коллекцию из поиска и медиатеки телефона. Кнопки громкости телефона меняют громкость ПК, в том числе через системный MediaSession. Выбор устройства задаёт, каким плеером управлять; уже звучащая музыка между устройствами автоматически не переносится. При отключении ПК его состояние остаётся выбранным, а воспроизведение не переключается самопроизвольно на телефон. Для нового набора метаданных и команд обновите Windows WeDex до 0.6.2.

Ссылка со схемой `wedex-cloud:` также открывает окно подключения с уже заполненным приглашением. Подключение подтверждается кнопкой в самом приложении.

Нужна одна доступная домашняя сеть и разрешённый входящий TCP-порт 8765 на ПК. Приглашение одноразовое, действует десять минут и содержит сертификат сервера. Проверка TLS остаётся включённой. Через мобильный интернет домашний ПК автоматически не публикуется. Установка сервера выполняется на ПК; Android подключается клиентом.

В Windows 0.7.0 появилась автонастройка VPS по SSH: [VPS_SETUP.md](VPS_SETUP.md). Android 0.6.2 подключается к ней по приглашению WeDex через интернет; домашняя сеть для этого режима не нужна. Установкой занимается ПК, телефон остаётся обычным клиентом. Мобильного входа на VPS по SSH пока нет.

Медиатека каждого устройства пока локальная. Облако переносит команды, состояние плеера и статистику; синхронизация сохранённых треков, Telegram-архив, постоянный кеш Hitmo и годовые карточки статистики ещё не реализованы.

## Сборка на Windows

Нужны установленный Rust/MSVC и Python 3. Скрипт установит JDK 21, Android SDK 35, NDK 28, Gradle 8.11.1, cargo-ndk 4.1.2 и Rust Android targets. Установка Android Studio не требуется. Дистрибутивы проверяются по контрольным суммам; инструменты находятся отдельно от системной Java.

```powershell
python tools/setup_android.py
python tools/build_android.py
```

Каталог инструментов по умолчанию — `.local/android-toolchain`. Его можно задать переменной `WEDEX_ANDROID_TOOLS`. Сгенерированная конфигурация — `.local/android-tools.json`, пути SDK для Gradle — `android/local.properties`. Эти файлы не включаются в Git.

Для одной архитектуры: `python tools/build_android.py --abi arm64-v8a` или `--abi x86_64`. Gradle упаковывает все уже имеющиеся `jniLibs`; для итогового универсального APK запускается сборка без `--abi`. Rust собирается в release с выравниванием ELF 16 КБ. Лицензии включены в assets APK.

Автотесты: `cargo test --workspace --locked`. Android Keystore проверяется инструментальными тестами `:app:connectedDebugAndroidTest`. Для них используйте отдельный эмулятор: Gradle может удалить целевое приложение после теста. Укажите `ANDROID_SERIAL`, если подключено несколько устройств.

Для изолированных ручных проверок есть Gradle-вариант `:app:assembleQa`: отдельный пакет `app.wedex.music.qa` с названием WeDex QA и отдельными данными. Он не используется как пользовательский дистрибутив.

Проверки этой сборки и оставшиеся ограничения перечислены в [ANDROID_VALIDATION.md](ANDROID_VALIDATION.md).

Журнал ошибок Android — `files/WeDex-errors.log` во внутреннем каталоге приложения. В отладочной сборке его можно прочитать через `adb shell run-as app.wedex.music cat files/WeDex-errors.log`. Токены редактируются перед записью; содержимое полей ввода в logcat не выводится.

## Обновления и подключения · 0.8

Приложение проверяет GitHub Releases и предлагает установить новый APK через системный установщик Android. Ключи сервисов и домен Hitmo синхронизируются через своё облако с шифрованием на устройствах. Инструкция и однократное обновление старого приглашения: [UPDATES.md](UPDATES.md). В портретной Sonora заголовок находится в строке управления, боковые карточки выходят за внутреннюю область карусели до края экрана.
