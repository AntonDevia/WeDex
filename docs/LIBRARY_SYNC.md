# Синхронизация коллекции · 0.11.0

«Понравившиеся» объединяются между Windows и Android через уже подключённое личное облако WeDex. Обновите приложения и сервер до 0.11.0. Повторная привязка не требуется. Встроенный сервер на ПК поддерживается тем же способом, но должен быть включён и доступен с другого устройства.

## Поведение

- При первом подключении к серверу объединяются локальные коллекции. Ключ записи — источник и его каталожный ID. По названиям записи автоматически не склеиваются. Идентификаторы Hitmo не зависят от домена зеркала.
- Лайк и снятие лайка сразу изменяют локальную коллекцию. Операция и изменение коллекции сохраняются одной транзакцией SQLite. Очередь отправки переживает закрытие приложения и не удаляется до подтверждения сервера.
- Сервер уведомляет нативные устройства об изменениях через существующий WSS. Передаются страницы изменений, а не вся коллекция. Периодическая сверка восстанавливает пропущенное уведомление.
- Удаление сохраняется в виде отметки без срока истечения. Начальное объединение другого устройства не может её перезаписать. При конкурентном добавлении и удалении приоритет получает удаление. После получения удаления трек можно добавить снова.
- Несколько действий на одном устройстве без сети сохраняют свой порядок. Сервер не полагается на часы телефона. Повторная отправка операции с тем же UUID не выполняет её заново.
- Импорт Яндекса пополняет общую коллекцию. Отсутствие записи в очередном импорте не является командой удаления общей коллекции. Снятие лайка в WeDex удаляет запись на всех устройствах, повторный импорт её не возвращает. Ошибочный ответ без массива записей отклоняется до импорта.
- Кэш, MP3, локальные пути, позиции загрузки и ссылки с временными параметрами не передаются. Домен Hitmo синхронизируется существующим отдельным механизмом подключений; адрес страницы песни разрешается через текущий домен при воспроизведении.

В медиатеке кольцо обозначает обмен с облаком, часы — ожидание подключения или подтверждения, галочка — завершённую сверку. При старом сервере изменения остаются в очереди до его обновления. Музыку можно слушать независимо от доступности сервера.

## Хранение и протокол

На сервере используются дополнительные таблицы существующей SQLite: `library_items`, `library_operations`, `library_clock`. Существующие таблицы не изменяются, версия схемы остаётся совместимой со старым сервером при откате. Резервная копия облака включает коллекцию вместе с остальной базой.

На клиентах: `library_state`, `library_known`, `library_outbox`, `library_hidden`, `library_active`. Курсор и очередь разделены по идентичности TLS-сертификата сервера. Переподключение к тому же серверу не запускает повторный начальный импорт. Очередь другого сервера не подтверждается сообщениями текущего.

Возможность сервера — `library-sync-v1`. Клиент отправляет `LibrarySync { cursor, operations }`, получает `LibraryDelta`, остальные нативные устройства — `LibraryChanged`. Страницы ограничены 128 записями, отправка также ограничивается объёмом до 180 КиБ для соблюдения лимита WebSocket. Если уведомление потерялось, фоновая сверка выполняется через 30 секунд.

Операция содержит UUID, метаданные трека, состояние лайка, наблюдавшуюся версию записи и необязательный UUID предыдущего действия того же устройства над этой записью. Сервер хранит ревизию последнего удаления. Не знающая об этом удалении операция не может его отменить. Ссылка на предыдущее действие учитывается только для того же устройства и трека; отклонённое действие не даёт знания о чужом удалении. Повтор UUID с другим содержимым или от другого устройства отклоняется.

Доступ к коллекции имеют только привязанные нативные устройства. Браузерному пульту чтение и изменение коллекции недоступны. Авторизация и закрепление TLS-сертификата остаются существующими. Метаданные на личном сервере хранятся в SQLite открыто; это не сквозное шифрование коллекции. Ключи сервисов продолжают использовать отдельное зашифрованное хранилище.

## Границы версии

Синхронизируются понравившиеся, их каталожные метаданные и отметка редакции трека. Пользовательские плейлисты, ручное расположение записей, таблица подмен аудио, музыкальные файлы и состояние офлайн-кэша не синхронизируются этим механизмом. Облако не может обеспечить воспроизведение записи, недоступной во всех подключённых источниках.

Удаление базы сервера при сохранении его сертификата не является восстановлением облака: нужно восстанавливать всю резервную копию согласованно. Записи об удалениях и обработанных операциях пока не очищаются, чтобы не терять корректность для долго отключённых устройств.
