# Установка VPS через WeDex Мастер

Начиная с 0.12.0 администрирование вынесено в отдельное приложение Windows `WeDex-Master.exe`. В музыкальном приложении нет SSH-настройки и локального сервера.

Поддерживаются Debian 12/13, Ubuntu 22.04/24.04, Linux x86_64 с systemd. Нужен root или пользователь с sudo. Другие дистрибутивы установщик пока не поддерживает.

1. Запустите «Мастер». Введите IP/домен SSH, SSH-порт, логин и пароль либо путь к ключу. Для пользователя с sudo укажите его пароль. При необходимости задайте отдельный публичный адрес. Порт WeDex по умолчанию 8765.
2. Нажмите «Установить / обновить по SSH». Сверьте отпечаток SSH с панелью хостинга. Изменившийся ключ также требует подтверждения.
3. «Мастер» проверяет ОС и ресурсы, передаёт встроенный Linux-бинарник, проверяет SHA-256, создаёт изолированного системного пользователя, systemd-службы, TLS-сертификат и проверяет HTTPS. Ранее установленные данные сохраняются; перед обновлением делается резервная копия.
4. Разрешите входящий TCP-порт WeDex в панели хостинга. При активном UFW установщик добавляет правило только для этого порта. SSH-порт не изменяется.
5. Адрес и SHA-256 TLS-сертификата из «Мастера» передайте пользователям. Они регистрируют личные аккаунты в «Настройки → Моё облако». SSH-пароли и административный ключ им не нужны.

Для существующей установки можно выбрать «Подключить установленную VPS». Административный ключ хранится отдельно в учётных данных Windows; старый ключ установленного WeDex подхватывается автоматически. Пароли SSH и sudo не сохраняются.

Кнопка «Обновить сервис на VPS» применяет опубликованный серверный релиз и показывает ход/результат. Для восстановления или установки встроенной версии используйте SSH-кнопку. При ошибке перезапуска сохраняется прежний исполняемый файл. Музыкальное приложение не имеет полномочий обновлять общий VPS.

Файлы: `/etc/wedex/server.json`, `/var/lib/wedex`, `/opt/wedex/current`, резервные копии `/var/backups/wedex`. Состояние службы: `systemctl status wedex`; журнал: `journalctl -u wedex`. Не публикуйте `identity.json`, закрытый TLS-ключ, логины/пароли или содержимое баз.

Аккаунты, безопасный перенос прежней личной базы и ограничения первой версии: [ACCOUNTS.md](ACCOUNTS.md).
