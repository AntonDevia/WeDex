# WeDex · Sonora

Нативное приложение для Windows и Android на Rust: рекомендации Last.fm, поиск по каталогам, распознавание с микрофона и единая локальная медиатека. Интерфейс — egui, аудио — rodio/Symphonia + CPAL. Приложение не запускает Python, Electron или yt-dlp.

Android 0.8.3: `dist/WeDex-Android-0.8.3/WeDex-0.8.3-Android.apk` (ARM64 + x86_64, Android 8.0+). Установка, особенности фонового плеера и сборка описаны в [docs/ANDROID.md](docs/ANDROID.md). Windows 0.6.2 передаёт обложку, очередь и состояние в основной плеер телефона; кнопки громкости телефона регулируют выбранный ПК.

Это первая рабочая версия, а не завершённый клиент всех перечисленных сервисов. Границы интеграций указаны ниже; интерфейс показывает ошибки сервисов, не подменяя результаты демонстрационными треками.

Скачать готовые сборки: [GitHub Releases](https://github.com/AntonDevia/WeDex/releases). Новая версия предлагает обновить приложение и подключённую VPS.

## Запуск

Актуальная Windows-сборка: `dist/WeDex-0.8.4/WeDex-Sonora.exe`. Встроен Linux-сервер для автонастройки VPS через «Настройки → Моё облако → Настроить VPS по SSH». Ввод IP/логина и пароля либо SSH-ключа, установка systemd-службы и подключение ПК выполняются из приложения. Поддержка ОС и инструкция: [docs/VPS_SETUP.md](docs/VPS_SETUP.md). Обновления ПК, Android и VPS, а также синхронизация ключей описаны в [docs/UPDATES.md](docs/UPDATES.md).

1. Откройте приложение и «Настройки».
2. В «Настройки → Подключения» нажмите строку нужного сервиса и добавьте ключ. Для Яндекса нужен OAuth-токен аккаунта с подпиской Плюс. Пароль аккаунта приложению не нужен. Инструкция: https://yandex-music.readthedocs.io/en/main/token.html
3. Нажмите «Сохранить и синхронизировать». Импортируются понравившиеся треки и список ваших плейлистов. Сохранённые подключения подхватываются автоматически.
4. Нажмите воспроизведение на Sonora для потока от своей коллекции. Можно выбрать трек в поиске и перейти в Sonora — очередь продолжится рекомендациями Last.fm. «Характер потока» настраивается в правом верхнем углу.

Предоставленный в чате ключ Last.fm сохранён локально в системном хранилище Windows; в исходный код и распространяемую сборку он не включён. Его можно добавить в настройках либо перенести через зашифрованную синхронизацию своего облака. Профиль Last.fm не требуется.

## Локальное облако · 0.6.2

В «Настройки → Моё облако» можно запустить сервер прямо в WeDex. VPS, Docker и Python для этого не нужны. Основное приложение остаётся клиентом; сервер использует отдельную SQLite и HTTPS/WebSocket. По умолчанию доступ разрешён только с этого ПК, порт 8765. Сервер останавливается при полном выходе из приложения; сворачивание в трей сохраняет его работу.

1. Запустите локальный сервер в настройках. Этот WeDex привяжется автоматически.
2. Нажмите «Пригласить браузер», затем «Открыть пульт». Одноразовое приглашение действует 10 минут. При первом открытии браузер покажет предупреждение о собственном сертификате локального сервера; для нативных клиентов доверенный сертификат передаётся внутри приглашения.
3. В браузере нажмите «Подключиться» и выберите играющий компьютер. Пульт поддерживает паузу/воспроизведение, предыдущий/следующий трек, перемотку после отпускания ползунка, громкость, shuffle, repeat и выбор трека очереди. Музыка звучит на выбранном ПК.
4. Для второго WeDex создайте отдельное приглашение кнопкой «Пригласить WeDex» и вставьте его в одноимённое поле другого клиента. У каждого устройства свой отзываемый ключ. Приглашение для браузера и приглашение для WeDex — разные форматы.
5. Для Android-приложения в домашнем Wi-Fi перед запуском включите «Доступ из домашней сети». При необходимости разрешите приложению входящие соединения в частном профиле Windows Firewall. Скопируйте приглашение WeDex на телефон и вставьте в «Настройки → Моё облако». Сертификат содержит LAN-адрес, определённый при первом создании сервера; изменение адреса роутером требует обновления сертификата в следующей версии мастера.

Плеер записывает реальные продвижения воспроизведения локально и отправляет сессии пакетами. Паузы, ожидание загрузки и скачки позиции при перемотке не считаются прослушанными минутами. Повторная отправка не дублирует запись. В прототипе отображаются суммарные минуты устройств и топ треков; общий календарь пользователя, годовые карточки, отдельный учёт исходящего трека crossfade и объединение пересекающихся сессий разных устройств относятся к следующим этапам.

Отдельный `WeDex-Server.exe` запускает ту же службу без интерфейса плеера: `WeDex-Server.exe --data-dir PATH --bind 127.0.0.1:8765`. Это Windows-сборка серверного пакета; Linux-код отделён от Windows UI и собирается командой `cargo build -p wedex-cloud --release --bin wedex-server`. Развёртывание Linux и автоустановка по SSH проверены на изолированной Debian 12 ВМ.

Android-приложение управляет ПК из обычного плеера и дзена, включая обложку, очередь и аппаратные кнопки громкости. Настройки телефона нужны только для подключения; устройство выбирается значком наушников в дзене. Windows устанавливает VPS по SSH; Telegram-архив и постоянный аудиокеш ещё не реализованы. Подробности: [docs/LOCAL_CLOUD.md](docs/LOCAL_CLOUD.md), [docs/VPS_SETUP.md](docs/VPS_SETUP.md).

## Обновление 0.2.0

- Ambient Sonora на всех вкладках; сервисы обозначены вашими прозрачными логотипами. Кнопки используют Font Awesome Classic Solid.
- Профиль, подключения, тема, переходы и поведение крестика собраны в «Настройки».
- Эквалайзер: 10 полос от 60 Гц до 16 кГц, ±12 дБ, отдельное предусиление и 18 пресетов. Изменение полос создаёт свою настройку.
- Плавный переход: от 0 до 12 секунд. Автоматическое наложение начинается, когда следующая запись уже подготовлена; при недоступном буфере сохраняется обычный переход. Пауза останавливает обе записи.
- Текст LRCLIB включается кнопкой слева от очереди. По умолчанию выключен; выбор сохраняется для всех песен. Синхронизированный текст следует за временем, щелчок по строке перематывает к ней. Обычный текст прокручивается; отсутствие текста — нормальное состояние.
- Громкость открывается вертикально при наведении на динамик. Дзен открывается щелчком по миниатюре плеера, стрелка сверху справа или Escape возвращают прежний режим окна.
- Крестик по умолчанию скрывает окно в трей, музыка продолжает играть. Щелчок по значку восстанавливает окно; меню значка содержит «Открыть WeDex» и «Выйти». В настройках можно выбрать полное закрытие.
- «Ближе к любимому» сильнее учитывает похожесть. «Больше открытий» расширяет поиск через похожих исполнителей и уменьшает приоритет самых очевидных совпадений.

## Возможности

- **Sonora:** `track.getSimilar`; при недостатке данных — похожие артисты и их треки. Есть исключение прослушанного, ограничение повторов исполнителя, настройка доли открытий и дозаполнение очереди. Это наш алгоритм на данных Last.fm, а не готовая персональная радиостанция Last.fm.
- **Плеер:** потоковая загрузка в память, воспроизведение, пауза, предыдущий/следующий трек, обложки, время, перемотка, громкость и десятиполосный эквалайзер с пресетами. Максимальный буфер одной записи — 128 МБ. Перемотка вперёд может ждать загрузки нужного фрагмента.
- **Очередь:** предыдущие, текущая и будущие записи. Рекомендации Last.fm сопоставляются с аудиокаталогами при запуске. Неразрешённую запись можно пропустить кнопкой следующего трека.
- **Поиск:** Яндекс, Hitmo, SoundCloud и YouTube Music опрашиваются вместе. Запуск — Enter или значок поиска. Сбой одного источника не уничтожает результаты остальных. Последние выбранные из поиска записи сохраняются локально.
- **Распознавание:** по нажатию микрофона записываются до 12 секунд. PCM преобразуется в моно 16 кГц с фильтрацией; Rust-ядро ShazamIO создаёт отпечаток. В Shazam передаётся отпечаток, запись на диск не сохраняется. Найденная запись показывается в отдельной панели; «Найти в каталогах» запускает поиск.
- **Медиатека:** локальное избранное разных сервисов, импорт понравившихся Яндекса и просмотр его плейлистов. Повторный импорт обновляет снимок Яндекса и сохраняет собственные добавления. Лайки в WeDex не изменяют аккаунты сервисов.
- **Версии:** правый клик по треку или многоточие у текущей записи. Сопоставляются исполнитель, название и длительность; live, remix, cover и другие отличающиеся записи отбрасываются. Кнопка воспроизведения сравнивает запись, «+» выбирает её, «Сохранить выбор» запоминает замену. «Оставить текущую» сбрасывает замену. Название источника открывает страницу записи.

## Интерфейс из Figma

У каждого источника своё окно подключения; его открывает строка в списке сервисов или логотип сервиса в меню. После вставки ключа или токена через 0,6 секунды запускается проверка, её результат отображается прямо в этом окне. Проверка не сохраняет ключ. Кнопка «Сохранить» изменяет только выбранный сервис. Для Яндекса используется OAuth-токен, для Last.fm — API-ключ, для SoundCloud — OAuth access token. YouTube Music имеет проверку доступности поиска без поля ключа. В Hitmo можно менять домен: маршруты поиска и песен, параметры запросов и внешние ссылки на аудио сохраняются. Старые сохранённые ссылки песен при воспроизведении обращаются к новому домену. Адрес Hitmo хранится в обычных настройках, секреты — в учётных данных Windows.

Источники поиска запускаются одновременно, найденные треки и исполнители появляются по мере ответов сервисов. Недоступный источник не задерживает выдачу остальных. В синхронизированном тексте колесо мыши временно отключает слежение: строки становятся одинакового размера и полной яркости. Через 3 секунды после последнего движения колеса активная строка снова центрируется и увеличивается вдвое; переход занимает 0,2 с. Это работает в панели текста и в дзене.

После запуска Sonora показывает одну стеклянную карточку «Запустить Sonora». Нажатие начинает подбор по понравившимся; если идёт импорт медиатеки, запуск ждёт его завершения. Карусель появляется после получения рекомендаций. При следующем запуске снова показывается стартовая карточка.

В поиске — отдельные источники «Все», «Яндекс», «Hitmo», «SoundCloud», «YouTube» с количеством результатов. В общем списке первым идёт совпадение Яндекса, затем результаты других каталогов по очереди; Hitmo не спрятан после всех треков Яндекса. Список прокручивается отдельно от шапки на всех размерах окна. Поиск по исполнителям использует каталог Яндекса: нажмите карточку артиста, чтобы открыть страницу с фотографией, доступными треками и кнопкой «Слушать». Каталог подгружается по 100 треков при приближении к концу списка; есть ручная загрузка и повтор после ошибки. Кнопка «В других источниках» ищет имя артиста и сразу выбирает Hitmo. Она не выдаёт результаты стороннего поиска за полный каталог артиста. Стрелка в карточке открывает остальные найденные имена.

Светлая и тёмная темы с выбором «Как в системе» в настройках, движущийся цветной фон Sonora, карусель, боковая навигация и плавающий плеер используют исходные компоненты Figma. Компоновка занимает размер окна: узкое меню сворачивается до значков, сетки меняют количество колонок, плеер переносит элементы в несколько строк. Минимальный размер окна — 360×480. Стекло размывает реальное содержимое через OpenGL, включая соседние обложки. Изображения экранов не используются как интерфейс. Эти изменения внесены только в приложение; документ Figma не изменён.

При перетаскивании таймлайна отображается выбранное время, а музыка продолжает играть. Переход выполняется один раз после отпускания мыши; обычный щелчок сразу выбирает время. Ошибки сервисов показывают уведомление «Что-то пошло не так» и записывают подробности в `WeDex-errors.log` рядом с исполняемым файлом. Сохранённые токены и ключи заменяются в логе на `[REDACTED]`. Под логотипом отображается версия сборки. Внизу меню — небольшие логотипы сервисов, для которых сохранено подключение.

Кнопки связаны с Rust-плеером и сервисами. Длинные списки понравившихся, плейлистов, очереди и версий прокручиваются внутри областей окна. Space — воспроизведение/пауза, стрелки — предыдущий/следующий, Escape — закрыть панель, F11 — полноэкранный режим. Анимации учитывают настройку Windows. Подробнее: [docs/NATIVE_UI.md](docs/NATIVE_UI.md).

Очередь заранее ищет три ближайшие рекомендации в каталогах. Следующий трек загружается в память и получает готовый декодер; при переключении используется эта подготовка, включая уже загруженные байты. Обложки ближайших восьми элементов запрашиваются независимо от видимости карточек. При сетевом обрыве загрузка продолжает чтение с сохранённой позиции через HTTP Range; повторный ответ без поддержки Range не дублирует байты. При начальном сбое адрес аудио запрашивается заново. Недоступные будущие рекомендации пропускаются; ошибка текущей записи не останавливает оставшуюся очередь. Подробности с сервисом и названием записи сохраняются в лог.

Кэш аудио временный, в памяти: текущая запись и один ближайший трек, не более 128 МБ для каждой. Доступность и скорость подготовки зависят от сервиса и сети.

## Что значит «без цензуры»

Программа ищет альтернативную запись, а не восстанавливает уже вырезанные слова. Отметка Explicit — только метаданные площадки. Трек с другой площадки получает статус «Версия не проверена». После проверки на слух пользователь может подтвердить оригинал; выбор сохранится в SQLite и будет применяться при включённой настройке предпочтения оригиналов.

Идея поиска альтернатив изучена по `R3DCyclops/mp3_PLRKLR`. Его GPL-код и Python-скрипты в приложение не переносились. Автоматической достоверной проверки цензуры по одному названию не существует в этой реализации.

## Реальный статус интеграций

| Источник | Реализовано | Проверка и ограничения |
| --- | --- | --- |
| Last.fm | Рекомендации и расширение через похожих артистов | Живой запрос к API вернул 30 рекомендаций |
| Яндекс Музыка | OAuth-токен, поиск, импорт понравившихся, плейлисты, полный MP3-поток | Нужна проверка с вашим токеном и подпиской; API неофициальный, старый `download-info` может быть ограничен сервисом |
| Hitmo | Сменяемый домен, старая HTML-разметка и новая Next.js/RSC, страницы песен, обложки и MP3 | На rus.hitmos.fm проверены 50 результатов и первые 8 КБ MP3. Разметка сайта может меняться |
| SoundCloud | Поиск официального API и полный MP3 HLS | Нужен OAuth access token зарегистрированного приложения. Токен обновляется вручную. AAC HLS, шифрованные HLS и превью вместо полного трека не поддерживаются; нужен живой тест с токеном |
| YouTube Music | Поиск через InnerTube; разрешение открытого audio/mp4 URL, если сервис его выдаёт | Живой поиск вернул 20 результатов. Подписанные/защищённые потоки, SABR и обязательная авторизация не реализованы; гарантировать встроенное воспроизведение YouTube нельзя. Можно открыть запись в сервисе |
| Shazam | Захват микрофона, Rust-отпечаток и HTTP-запрос, поиск распознанного трека | Неофициальный endpoint; нужен сквозной тест с реальным звуком. Микрофон при автоматических проверках не включался |

Приложение устанавливается самостоятельно на Windows. Яндекс Музыка служит источником каталога и аудио, не платформой размещения приложения.

## Разработка

Требуются Rust stable и Visual Studio Build Tools с компонентами C++/Windows SDK. Rust был установлен в `%USERPROFILE%\.cargo\bin` без изменения системного PATH.

```powershell
& "$env:USERPROFILE\.cargo\bin\cargo.exe" run --bin sonora
& "$env:USERPROFILE\.cargo\bin\cargo.exe" test --locked
& "$env:USERPROFILE\.cargo\bin\cargo.exe" build --release --locked --bin sonora
```

В `scripts/` также есть сценарии запуска, проверок и упаковки. На этой машине запуск `.ps1` ограничен политикой PowerShell; команды Cargo выше работают без изменения этой политики. Готовый `.exe` запускается обычным двойным щелчком.

Или стандартные `cargo run --bin sonora`, `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo build --release`. `Cargo.lock` фиксирует версии зависимостей.

Для отдельных сетевых проверок: `cargo test providers::live -- --ignored --nocapture`. Это проверки доступности: вывод внешних каталогов может содержать ошибку сервиса даже при успешном завершении диагностического теста. Unit-тесты работают без внешней сети и аккаунтов.

Сквозная проверка адаптера Hitmo: `cargo test live_hitmo_search_and_audio -- --ignored --nocapture`. Проверяет поиск, разрешение страницы песни и заголовок MP3 в первых 8 КБ потока.

Ключи берутся из Windows Credential Manager (`WeDex.Sonora`, имена `yandex`, `lastfm`, `soundcloud`). Для разработки также поддерживаются переменные `WEDEX_YANDEX`, `WEDEX_LASTFM`, `WEDEX_SOUNDCLOUD`. Не коммитьте токены. Начальная загрузка Last.fm из `.local/lastfm.key` предназначена только для локальной разработки; `.local/` игнорируется Git.

База и настройки: `%LOCALAPPDATA%\WeDex\Sonora\data\library.sqlite3` (фактический путь определяется `directories::ProjectDirs`). Аудиобуфер, микрофонная запись и временные ссылки потоков не сохраняются в базе. История ограничена 500 записями; последние 100 используются для исключения повторов после перезапуска.

Архитектура и следующие технические шаги: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Происхождение ядра распознавания: [THIRD_PARTY.md](THIRD_PARTY.md).
